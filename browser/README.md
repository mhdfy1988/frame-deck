# 无模型浏览器版

与本机完整版共用一个仓库。`npm start`仍运行原本机版；本目录仅构建静态网页，不需要Python或模型。浏览器构建直接沿用`web/index.html`、`web/style.css`和原图标体系，保留左侧步骤导航、抽帧／整理／精修／导出四屏及原精修弹窗，不再另做简化界面。无模型处理及浏览器解码的必要差异仍单独说明，不宣称两版所有像素结果完全等价。

## 操作

1. 在原抽帧屏右上选择视频，设置底部开始／结束秒数与采样帧率后提取；也可从邻近“导入PNG”导入同尺寸序列，默认按文件名自然排序。PNG直接作为帧导入：单图为1帧，多图为序列，不生成动画。图片模式显示“源图片”、左侧“导入”，隐藏视频参数并清理旧时间／估算；选择视频后恢复抽帧模式。结果仍在右侧帧列表，点击打开原尺寸预览。新结果完整成功才替换旧序列，未导出内容会先确认。
2. 从左侧“帧处理”进入原整理屏，点击原帧查看；复选框、全选／取消勾选和播放勾选帧保留。拖动交换两帧位置，Alt＋左右键使用相同规则。可单帧或勾选删除；原撤销／恢复／重置覆盖顺序、删除和循环裁剪，不覆盖像素精修。删空后可撤销或重置恢复。
3. 寻找循环复用原算法，在浏览器工作线程分析；没有可靠候选时不强凑。原弹窗中选择候选并预览，点击“只保留这个循环”后裁剪该帧段，支持撤销。
4. “纯色去背”复用EazyCut：自动从首个保留帧的原图边缘估算多数底色，整组共用；也可取消“自动底色”手动选色，或点击“取色”后在当前原图上点击（Esc取消）。容差控制颜色差异，柔边控制透明过渡，去底色用于减轻半透明边缘的底色污染；修改参数后需主动点击执行。默认“仅边缘连通”保护封闭区域；取消后可去除手臂间等封闭同色背景，也可能误删主体同色部分。每次均从原图重算，确认后覆盖已有去背／精修结果；整组完成才替换，取消／失败保留上一组结果。适合较一致纯色背景，不是AI分割或复杂背景画质保证。
5. 在原“抠图与精修”屏双击当前图或帧卡片打开原双栏编辑器：去除／恢复画笔、魔法棒与编辑历史；自动保存回当前帧，关闭／Esc等待未完成保存。没有先运行去背也可直接精修。保存只改变该帧，不改其他帧。关闭再打开会创建新的精修历史，原图仍保留供恢复画笔使用。
6. 从左侧“导出”进入原整屏导出页，而非弹窗；设置名称、帧率、尺寸、共同范围裁剪、留白与采样，保留输出播放、图集预览、适配／100%和框选裁剪。生成PNG序列＋`frame-sequence.json`，或精灵图＋`sheet.json`的ZIP。共同范围对全部保留帧统一测量，不逐帧居中。留白限制在原画布内，不扩展边界。原尺寸、不裁剪的序列直接使用现有PNG字节。

刷新或关闭页面丢失当前会话，离开前导出。所有图片、视频和中间结果留在浏览器内存；不存在服务器上传、模型下载或隐藏API回退。普通网页／运行库仍需从静态站点加载，不代表首次访问可离线。

纯色去背的容差、柔边、去底色使用滑块并实时显示数值；聚焦后可用方向键逐值微调、Home／End到达边界。范围分别为0–100、0–50、0–100，仍需点击执行才处理图片。

## 构建、预览与验证

在仓库根目录执行：

```powershell
npm.cmd ci
npm.cmd run build:browser
npm.cmd run preview:browser
```

预览为 http://127.0.0.1:8904/frame-deck/ ，不依赖8902。线上入口为 https://mhdfy1988.github.io/frame-deck/ 。`output/browser-site/frame-deck/`才是Pages上传目录；测试和预览的外层目录不应一起上传。`.github/workflows/pages.yml`在`main`的浏览器构建输入发生变更或手动触发后检查、构建并部署；仅文档变更不重复部署，不创建Tag或GitHub Release。

发布构建先运行`node scripts/prepare-browser-sources.mjs`，下载清单锁定的19份第三方源码归档并核对SHA-256；再设置`FRAMEDECK_RELEASE=1`构建，缺失或哈希不符会失败。归档只供用户按需下载，不由应用执行或自动加载；站点页脚可打开“许可与源码”。`build-info.json`记录版本、CI提交及文件哈希。原本机版仍按原命令启动，不受Pages部署影响。

```powershell
npm.cmd run check:browser-format
npm.cmd test
npm.cmd run build:browser
npm.cmd run test:browser-static
```

静态测试自己启动临时端口，运行真实Chrome和WASM、生成合成素材并回读下载ZIP／PNG；不需要8904预览或Python服务。本机FFmpeg仅用于测试时制作输入视频，不参与网页实际处理；需可从命令行调用。输出位于忽略的`output/pages-evidence/`。

线上验收可在独立终端设置`$env:FRAMEDECK_TEST_URL='https://mhdfy1988.github.io/frame-deck/'`后运行同一静态测试；其界面、WASM与运行资源取自线上，参考算法仅在测试浏览器内拦截提供，不部署测试入口。测试不会改用户页面或上传输入素材。另核对线上`build-info.json`的提交及实际下载资源哈希。

## 容量与差异

- 推荐新版桌面Chrome。当前只验证Windows Chrome，未做Safari、Firefox、移动设备或大视频性能验收。
- 视频／单PNG最多64MiB，每组1–600帧、单边4096像素、单帧1200万像素；PNG序列累计、抽帧／去背结果与输出ZIP各最多96MiB。移除原先2400万整组像素限制，序列不必同时解码为RGBA；仍明确拒绝真实容量超限，不静默裁切或降低画质。600与96MiB是当前实现保护策略，不是GitHub Pages限制，也不表示600张任意尺寸均已验证。
- 视频使用官方单线程FFmpeg.wasm，首次抽帧加载约32MB运行库；可取消，单次探测30秒、抽帧120秒限时。它不是AI模型，也无需SharedArrayBuffer／跨域隔离响应头。
- 抽帧每批最多16帧且不超过1600万像素，读出后逐个删除WASM临时PNG；完成整组后才替换会话，取消或失败不留下半组。批次在同一重采样序列上按帧号分割，不在批边界重新起算采样相位。固定运行库各批仍需解码前面的片段，以额外计算换取较小临时文件占用，不宣称总耗时或进程内存峰值一定下降。各批共享120秒解码期限。
- 列表使用最长边192像素缩略图，生成按队列顺序执行；大图预览保留原尺寸，全尺寸URL缓存最多8项。去背与共同裁剪逐帧处理；序列ZIP逐文件、每块最多1MiB写入，仍需保留最终下载Blob，不是零内存或直接流式写磁盘。精灵图仍需一张完整画布，沿用原单边8192／1600万像素限制，超限请调整图集输出设置，不自动缩小。
- 当前实测：约10.04秒、1280×720动态视频，以12帧/秒分8批获得121帧，与同版本WASM一次性抽取逐帧RGBA哈希一致；整组PNG重新导入、去背与原尺寸ZIP回读通过。测试样本不是用户原视频；更长序列、4K与多浏览器性能仍待验证。
- 视频预览的总时长可能包含更长的音轨；抽帧探测后以视频轨为准同步时间上限，选择直到末尾时同步结束值，手填越界范围仍明确拒绝。
- 视频采用`trim → setpts → fps(round=up)`重采样，可能重复或舍弃源帧；与本机版按真实PTS抽帧的实现不等价。清单`sampleTimeSeconds`是请求采样点，不能当作解码源帧精确PTS；未知真实PTS的`sourceTimeSeconds`为null。帧数与预计不符时明确拒绝，不把缺帧补成成功。VFR、旋转、特殊编解码器及大视频尚未全面验收。
- 帧序与循环复用原算法；图片裁剪／缩放在Canvas执行。最近邻可用，平滑采样使用浏览器实现，不声称与Pillow Lanczos像素一致。RGBA原尺寸序列避免重新编码；发生Canvas绘制后不保证透明像素中的隐藏RGB字节不变。
- 精修器适配限于构建时固定嵌入身份、资源路径和通信。原像素算法不改；不通过网络伪造后端，也不覆盖全局fetch。上游文件适配点变化时构建失败。
- 已知固定core 0.12.10的ffprobe成功也可能返回-1；适配显式记录警告，仅在JSON、尺寸、时长及错误日志校验后接受，其他错误失败，不回退到旧解码或HTML视频截屏。
- 序列／图集沿用FrameDeck既有清单类型，但未验证所有下游工具或引擎导入；不是引擎原生格式。AI模型、模型安装、持久工程、批量多动作和云端服务均不包含。

## 模块与来源

- `session.js`：图片、修订和唯一帧编辑会话；顺序及历史复用`web/organizer-core.js`。
- `video.js`、`images.js`：输入预算、解码与取消，成功时才移交会话。
- `tasks.js`、`pixel-worker.js`：循环与背景处理的工作线程生命周期、整组共享底色、逐帧解码和取消清理；循环复用原算法。`keying/core.js`为EazyCut固定源码快照，`keying/color-distance.js`隔离Culori色差计算；原魔法棒仍用于手工精修。
- `ui/keying-controls.js`：仅拥有参数草稿与原图取色交互，不拥有像素或会话；批处理由主入口协调，`session.js`一次替换整组。
- `export.js`：共同可见范围与Canvas变换；参数／几何复用`web/export-core.js`。`archive.js`独立拥有增量ZIP、下载Blob预算与取消清理，复用已有fflate，不新增依赖。
- `scripts/browser-template.mjs`：从原HTML生成浏览器入口，只适配同源路径、无模型说明及必要PNG／纯色去背控件，适配点变化立即失败；原CSS完整保留，仅追加`compat.css`最小补充。此前独立新布局的模板、样式与组件已移除，不留隐藏回退。
- `ui/extract.js`、`organizer.js`、`matting.js`、`export-panel.js`及`dialogs.js`：各自绑定原屏幕所属根节点，业务仍通过同一个会话和现有算法；`main.js`只协调四屏、任务与会话。`media.js`管理图片URL和观察／播放生命周期，替换图片后释放旧URL。
- 构建来源、已知差异和上游证据见[源码证据](../docs/source-evidence.md)；第三方WASM不是MIT代码，许可与源码交付见[第三方说明](../THIRD_PARTY_NOTICES.md#无模型浏览器版新增依赖)。
